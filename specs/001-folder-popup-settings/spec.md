# Feature Specification: 文件夹组件完善 — 全局设置与鼠标位置弹窗

**Feature Branch**: `001-folder-popup-settings`

**Created**: 2026-05-22

**Status**: Draft

**Input**: User description: "完善项目里的文件夹组件。list模式下统一全局行高设置，条目在文件夹未展开时也可点击，点击文件夹在鼠标位置弹出窗口并自动贴紧边界，添加测试数据。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全局统一列表行高 (Priority: P1)

用户在设置面板中统一设置列表模式下所有文件夹的行高。修改后，所有使用列表模式的文件夹立即应用新的行高，无需逐个文件夹调整。

**Why this priority**: 这是当前架构中明确存在的问题——行高按文件夹单独配置不符合用户预期，且修复后直接影响日常使用体验。

**Independent Test**: 在设置面板修改行高数值，验证所有列表模式文件夹的行高同步变化。

**Acceptance Scenarios**:

1. **Given** 用户打开了设置面板，**When** 调整列表行高滑块，**Then** 所有处于列表模式的文件夹行高实时更新。
2. **Given** 某文件夹处于卡片模式，**When** 用户在设置面板修改行高后切换该文件夹为列表模式，**Then** 该文件夹使用全局行高值。
3. **Given** 用户刷新页面，**When** 页面加载完成，**Then** 文件夹列表行高恢复为上次设置的全局值。

---

### User Story 2 - 鼠标位置弹出文件夹面板 (Priority: P1)

用户点击文件夹图标时，在鼠标当前位置弹出一个浮动面板展示文件夹内容。如果鼠标靠近页面边界，面板自动贴紧边界，尽可能靠近鼠标位置。

**Why this priority**: 这是文件夹交互的核心改进，直接影响文件夹内容浏览的用户体验，与全局设置同等重要。

**Independent Test**: 点击任意文件夹，验证弹出面板出现在鼠标附近，并在靠近边界时正确贴紧。

**Acceptance Scenarios**:

1. **Given** 文件夹在页面中央区域，**When** 用户点击文件夹，**Then** 弹出面板以鼠标点击位置为基准居中显示。
2. **Given** 文件夹靠近页面右边缘，**When** 用户点击文件夹，**Then** 弹出面板右移至贴紧右边缘，不超出视口。
3. **Given** 文件夹靠近页面底部，**When** 用户点击文件夹，**Then** 弹出面板上移至贴紧底部边缘，确保面板完整可见。
4. **Given** 文件夹靠近页面左上角，**When** 用户点击文件夹，**Then** 弹出面板向右下方展开，贴紧左边缘和上边缘。
5. **Given** 弹出面板已打开，**When** 用户点击面板外部区域或按 Esc 键，**Then** 面板关闭。
6. **Given** 弹出面板已打开，**When** 用户点击另一个文件夹，**Then** 当前面板关闭，新文件夹面板在新的鼠标位置弹出。

---

### User Story 3 - 条目直接点击 (Priority: P2)

文件夹中的每一个条目（网页链接）在文件夹未展开时也显示为可点击状态。用户无需先展开文件夹再点击条目——当文件夹处于收起状态时，其内部条目通过弹窗展示后即可直接点击访问。

**Why this priority**: 这增强了弹窗面板的实用性，确保弹窗中的条目本身就是可交互的。

**Independent Test**: 打开文件夹弹窗后，点击其中的条目，验证导航到对应网页。

**Acceptance Scenarios**:

1. **Given** 弹出面板已打开并显示文件夹内容，**When** 用户点击面板中的网页条目，**Then** 在新标签页打开对应网页链接。
2. **Given** 弹出面板已打开且处于列表模式，**When** 用户点击条目，**Then** 条目响应点击并导航，与其他交互（如拖拽）不冲突。

---

### User Story 4 - 测试数据填充 (Priority: P1)

前端页面预置测试用的文件夹和网页条目数据，确保打开页面时有内容可见、可交互，方便开发和测试。

**Why this priority**: 没有测试数据，所有其他功能都无法验证，这是开发测试的前提。

**Independent Test**: 启动前端开发服务器，打开页面，验证能看到多个文件夹和网页条目。

**Acceptance Scenarios**:

1. **Given** 前端服务启动且数据库为空，**When** 用户打开页面，**Then** 页面显示至少 3 个测试文件夹和若干测试网页条目。
2. **Given** 测试数据已加载，**When** 用户对测试文件夹执行展开/收起操作，**Then** 操作正常响应，展示预期的测试条目。

---

### User Story 5 - 从文件夹弹窗拖拽条目到主面板 (Priority: P1)

用户可以打开文件夹弹窗后，按住弹窗中的条目并拖拽到弹窗外部区域，松开鼠标后该条目从文件夹中移出，出现在主面板上。拖拽过程中文件夹弹窗保持打开，不会被关闭。

**Why this priority**: 这是用户管理文件夹内容的核心操作，直接影响文件夹内条目的整理效率。

**Independent Test**: 打开文件夹弹窗，拖拽一个条目到弹窗外并松开，验证条目出现在主面板且从弹窗中消失。

**Acceptance Scenarios**:

1. **Given** 文件夹弹窗已打开，**When** 用户按住弹窗中的条目并拖拽到弹窗外部区域，**Then** 弹窗显示提示文字"松开鼠标移出文件夹"。
2. **Given** 用户已将条目拖到弹窗外，**When** 松开鼠标，**Then** 条目从文件夹中移出，出现在主面板网格中。
3. **Given** 拖拽过程中，**When** 条目仍在弹窗范围内，**Then** 弹窗保持打开，提示文字显示"拖到面板外以移出文件夹"。
4. **Given** 用户在弹窗内拖拽但未拖出弹窗，**When** 松开鼠标，**Then** 条目保留在文件夹中，弹窗保持打开。
5. **Given** 拖拽正在进行中，**When** 用户点击弹窗外部区域，**Then** 弹窗不关闭，直到拖拽操作完成。

---

### User Story 6 - 弹窗内条目右键菜单 (Priority: P2)

用户在打开的文件夹弹窗内，右键点击任意条目可以弹出标准的上下文菜单，与主面板上的右键菜单功能一致（切换视图模式、新标签页打开、复制链接、添加到 Dock、移动到其他文件夹等）。

**Why this priority**: 弹窗内条目缺少右键菜单导致用户必须先将条目移出文件夹才能进行管理操作，降低了使用效率。

**Independent Test**: 打开文件夹弹窗，右键点击弹窗内的任意条目，验证弹出与主面板一致的上下文菜单。

**Acceptance Scenarios**:

1. **Given** 文件夹弹窗已打开且处于图标模式，**When** 用户右键点击弹窗内的条目，**Then** 弹出上下文菜单，包含视图切换、新标签页打开、复制链接等选项。
2. **Given** 文件夹弹窗已打开且处于列表模式，**When** 用户右键点击弹窗内的条目，**Then** 弹出相同的上下文菜单。
3. **Given** 弹窗内条目右键菜单已打开，**When** 用户选择"移动到文件夹"选项，**Then** 条目被移动到目标文件夹，当前弹窗内容更新。

---

### Edge Cases

- 鼠标在页面角落点击时，弹出面板同时贴紧两条边界。
- 视口尺寸变化（如窗口缩放）时，已打开的弹窗位置是否需要重新计算？——关闭当前弹窗，用户重新点击即可。
- 全局行高设置为极小或极大值时，列表条目是否保持可读性？——通过设置滑块的合理范围限制（如 20–60px）。
- 测试数据与正式数据共存时如何区分？——测试数据仅在数据库为空时自动填充。
- 文件夹内最后一个条目被删除时，文件夹自动删除，不会出现空文件夹场景。
- 从弹窗拖出最后一个条目时，文件夹应自动删除（复用已有的空文件夹自动删除逻辑）。
- 拖拽弹窗内条目时如果用户按 Esc，应取消拖拽操作，条目保留在文件夹中。
- 右键菜单在弹窗内条目上弹出时，菜单位置不应超出视口边界。

## Clarifications

### Session 2026-05-22

- Q: 当文件夹包含大量条目时，弹出面板应该如何处理溢出？ → A: 弹出面板设最大高度（视口高度的 70%），内容超出时内部滚动。
- Q: 移除每个文件夹的行高设置后，视图模式切换（卡片/列表）的控制应放在哪里？ → A: 在弹出面板内顶部放置模式切换按钮，直接在弹窗内切换。
- Q: 当用户点击一个空文件夹时，弹出面板应如何表现？ → A: 不允许空文件夹存在。当文件夹内最后一个条目被移除后，文件夹自动删除。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供全局的列表行高设置项，位于设置面板中，所有文件夹共享该设置值。
- **FR-002**: 系统必须在用户点击文件夹时，在鼠标当前位置弹出浮动面板展示文件夹内容。
- **FR-003**: 弹出面板必须具备边界检测能力：当面板尺寸超出视口时，自动贴紧最近的边界，确保面板完整显示在视口内。面板最大高度不超过视口高度的 70%，内容超出时在面板内部滚动。
- **FR-004**: 弹出面板中的条目必须可直接点击并导航到对应网页。
- **FR-005**: 系统必须支持通过点击面板外部区域或按 Esc 键关闭弹出面板。
- **FR-006**: 当用户点击另一个文件夹时，当前弹出面板必须关闭并在新的鼠标位置弹出新面板。
- **FR-007**: 系统必须在首次启动（无数据）时自动创建测试数据，包含至少 3 个文件夹和 6 个网页条目。
- **FR-008**: 全局列表行高设置必须持久化，刷新页面后保留之前的设置值。
- **FR-009**: 移除现有的每个文件夹单独设置行高的功能，统一使用全局设置。
- **FR-010**: 弹出面板应支持在卡片模式和列表模式之间切换（复用现有 folderViewMode 设置）。模式切换按钮位于弹出面板顶部，取代原有的 FolderSettingsPopup。
- **FR-011**: 系统不允许空文件夹存在。当文件夹内最后一个条目被移除或删除时，该文件夹必须自动删除并从页面移除。
- **FR-012**: 弹出面板点击外部区域时必须在一次点击内关闭，不应需要多次点击。
- **FR-013**: 右键点击文件夹时，上下文菜单中应提供可视化的大小选择器，以小型网格图形展示可选尺寸（1×1, 2×2, 3×2, 2×3, 3×3），当前激活尺寸应高亮显示。
- **FR-014**: 用户按住 Alt 键拖拽一个网页条目到另一个网页条目上并松开鼠标时，应在目标位置原地生成一个新文件夹，并将两个条目移入该文件夹。
- **FR-015**: 用户按住 Alt 键拖拽一个网页条目到已有文件夹上并松开鼠标时，应将该条目加入该文件夹。
- **FR-016**: 文件夹弹窗中的条目必须支持右键上下文菜单，包含与主面板一致的菜单选项（视图切换、新标签页打开、复制链接、添加到 Dock、移动到文件夹、从文件夹移出等）。
- **FR-017**: 用户可以按住文件夹弹窗中的条目并拖拽到弹窗外，松开鼠标后该条目从文件夹移出到主面板。
- **FR-018**: 拖拽过程中文件夹弹窗必须保持打开，不被关闭。拖拽期间点击弹窗外部不应触发关闭。
- **FR-019**: 右键选择文件夹大小后，文件夹的网格尺寸必须立即更新。此功能依赖后端 UpdateTool API 正确更新 size 字段。
- **FR-020**: 文件夹大小变更时，文件夹必须以左上角为锚点原地扩展。如右侧无空间则移至下一行。不得跳到第一行或完全重新排列。
- **FR-021**: 文件夹折叠态下，列表模式中的条目预览必须可直接点击并打开对应网页，与图标模式行为一致。
- **FR-022**: 文件夹弹窗内的网页条目外观必须与主面板一致。弹窗内使用与主面板相同的组件渲染条目。
- **FR-023**: 通过拖拽或右键菜单将条目移出文件夹后，如果源文件夹变为空，该文件夹必须自动删除。
- **FR-024**: 禁止文件夹嵌套。文件夹不能通过 Alt+拖拽、右键菜单或 API 移入另一个文件夹。
- **FR-025**: 列表模式下的条目也可以从弹窗拖出至主面板。拖出后以 1×1 卡片显示。

### Bug Fixes

- **BUG-001**: 右键菜单选择文件夹大小不生效。根因：`service/tools.go` 中 `UpdateTool` 函数的 SQL UPDATE 语句有 15 个占位符但 `stmt.Exec()` 传了 17 个参数（`folder_view_mode` 和 `folder_item_size` 从 SET 子句被移除但参数未同步清理），导致 WHERE 子句拿到错误值。修复：恢复 SET 子句中的 `folder_view_mode` 和 `folder_item_size` 列。
- **BUG-002**: 修改文件夹大小后文件夹跳到第一行。根因：`UpdateTool` 将 auto-layout 未持久化的 gridX=-1 写回 DB，`buildLayout` 将其视为新项排到首位。修复：`UpdateTool` 检测到 gridX/gridY 为负值时从 DB 保留现有值。

### Key Entities

- **全局设置（GlobalSettings）**: 包含列表行高（listItemSize）等站点级配置项，作用于所有文件夹。
- **文件夹（Folder）**: 一个容器类条目，包含子条目。保留 folderViewMode（卡片/列表切换），但不再存储单独的行高值。
- **弹出面板（PopupPanel）**: 在鼠标位置展示文件夹内容的浮动窗口，具备边界检测和贴紧能力。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在设置面板修改列表行高后，所有列表模式文件夹在 1 秒内完成视觉更新。
- **SC-002**: 弹出面板在 100% 的情况下完整显示在视口内，不出现裁剪或溢出。
- **SC-003**: 弹出面板从鼠标点击到显示的响应时间不超过 200 毫秒，交互流畅。
- **SC-004**: 首次打开页面时能看到测试数据，无需手动创建即可开始交互测试。
- **SC-005**: 弹窗中的条目点击后 100% 能正确导航到目标网页。

## Assumptions

- 现有的 `FolderSettingsPopup` 组件将被移除，其视图模式切换功能整合到弹出面板顶部的切换按钮中，行高设置移至全局设置面板。
- 弹出面板使用固定定位（fixed/absolute）实现，不在 DOM 流中占据空间。
- 测试数据通过后端 API 在首次初始化时注入，或通过前端种子数据提供。
- 弹出面板的位置计算基于鼠标点击坐标和视口尺寸，不需要考虑滚动偏移（因页面可能不滚动）。
- 现有的 `InlineFolderPanel` 将被替换或重构为鼠标位置弹出的新面板。
- `folderViewMode`（卡片/列表切换）仍保留在每个文件夹上，因为这是文件夹级别的展示偏好。
